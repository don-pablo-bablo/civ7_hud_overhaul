# Agent guide

Read [CONTRIBUTING.md](CONTRIBUTING.md) first. It has the layout of the code,
the code rules and the writing style. Everything below is extra, for agents
only.

## Working with the maintainer

- **Testing**: the maintainer tests by playing and by looking at the browser
  mock. They do not read the code. Explain every change by what it looks like
  or does in game.
- **Restarts**: every time something is to be checked in game, say whether it
  needs a game restart.
- **Previews**: for anything the player sees, show it first in the mock or in
  the game, and commit only once the maintainer approves it. When a layout
  choice is open, offer two to four previews to choose from. Logic fixes
  checked in the live game can be committed straight away.
- **Launches**: starting the game is the maintainer's call. Ask first.
- **Decisions**: raise any design choice that changes what players see
  instead of applying it silently.

## Tools

civ7lab lives in `../civ7lab`, installed as the `civ7lab` command.

- **Mock**: `civ7lab mock serve`, as in CONTRIBUTING.md.
- **Live**: with the game running and the inspector on, `civ7lab live eval
  '...'` runs code in the game's UI. `--file tools/live/measure.js` reports
  where each HUD piece sits.
- **Previews without a restart**: add a `<style>` with its own id to
  `<head>` through `live eval` to try CSS. A changed or new script can be
  loaded with `import("fs://game/pablo-hud-overhaul/ui/<file>.js")`; a
  component it defines then needs `Controls.initializeComponents()`, which
  the game runs once at load. Both last until the next restart.

## Commits

Do not add AI co-author or "generated by" lines to commits or pull requests.
